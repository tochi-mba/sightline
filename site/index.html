What Sightline is

One app for the camera you already own.

Sightline is an Android app, a Windows app and a command line built around the protocol of one Generalplus camera. The protocol was measured on that camera and is written down in the open. Other cameras are not presented as supported until they have dated evidence.

What it does

What has worked on the reference hardware.

These are dated observations, not a roadmap presented as a finished product. The complete record—including failures and checks not yet run—is in the acceptance record.

Connect and disconnect

The Windows command line joined and left the reference camera. Its adapter choice kept the PC's default route on a separate tethered internet link.

Capture a real frame

sightline snapshot completed through the full stack and saved a picture from the reference camera.

Read the camera's menu

The camera returned an 18,523-byte parameter file in 38 chunks, parsed as 21 settings across four categories.

Inspect status

The reference camera acknowledged status requests with a 16-byte payload, and the command-line status check passed.

Decode the measured stream

RTSP setup and playback succeeded; all 28 captured frames reassembled into valid 640×360 JPEGs at about 12.2 frames per second.

Find and configure from Windows

The Windows app found the camera, connected, and displayed its real settings and firmware in the REX theme.

Explain a picture failure

When its picture failed, the Windows app showed a reason rather than leaving a black view.

Current limitation: Windows live view

The Windows app's live picture has not passed. It reads the menu before starting the stream, after which RTSP is unanswered.

Not yet accepted

Taking a photo, toggling recording, changing a setting, and listing, downloading or deleting card files have no dated pass yet.

Install

Start with the release notes.

Preview packaging can change. GitHub's latest release is the source of truth for requirements, checksums and installation notes.

On Android

  1. Open the latest GitHub release. Confirm that it actually contains Sightline.apk and read that release's notes.
  2. Download the APK on the Android device. Follow Android's own prompts for a package obtained outside its app store.
  3. Treat it as unverified hardware support. The acceptance record contains no dated Android on-device pass yet.

On Windows

  1. Open the latest GitHub release. Choose Sightline-Setup.exe, Sightline-Portable.exe or sightline-cli.exe only when that exact asset is attached.
  2. Read the release notes. They carry the current Windows requirements and integrity information; this page does not guess them.
  3. Use the command line for the accepted path. On the reference PC, these operations passed on 2 October 2026: 
    .\sightline-cli.exe adapters
.\sightline-cli.exe connect --ssid ActionCam_…
.\sightline-cli.exe settings
.\sightline-cli.exe snapshot --out frame.jpg

FAQ

Questions, answered plainly.

Is Sightline finished?

No. The Windows command-line path has passed several end-to-end checks on one camera, but the Windows app's live view fails and Android has no dated on-device acceptance. The acceptance record is the source of truth.

What happened to the PC's internet during the test?

On 2 October 2026, the reference PC joined the camera through a TP-Link USB Wi-Fi adapter while its default route stayed on a tethered link. An HTTP request still succeeded. The Android/mobile-data case was not run.

Does the Windows app show live video?

Not yet. That acceptance check currently fails because the app reads the menu before starting the stream and RTSP is then unanswered. The command-line snapshot path did pass.

Will another Generalplus camera work?

It might, but there is no dated evidence yet. Only the reference camera on firmware 20240708 V1.3 is represented as tested.

Why do download controls sometimes open the release page?

The page creates a direct download only after GitHub reports the exact asset on the latest release. If no release exists, an asset is missing, or the API cannot be reached, it falls back to the release page instead of guessing a URL.
